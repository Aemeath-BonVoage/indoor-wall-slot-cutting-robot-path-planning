# Roadmap

目标：把毕设原型升级为一个**可复现、可扩展、可做研究**的移动操作机器人项目。

每个阶段完成的标准都是**在 Gazebo / RViz 中实际跑通并留下可复现的命令或数据**。

---

## 阶段 0 · 工程基础与稳定性

- [x] git 仓库、`.gitignore`、README
- [x] 修复 `package.xml` 依赖声明（Humble 下 `rosdep install` 可用）
- [x] 一键启动：`scr_bringup` 包，单条命令启动 仿真 + 导航 + RViz
- [x] 轻量模式：`gui:=false`（无 Gazebo 窗口）、`rviz:=false`，适配低内存机器
- [x] 修复导航 launch 默认地图路径（`map.yaml` → `my_map.yaml`）
- [x] 修复 Ctrl+C 退出时 `rclpy.shutdown()` 重复调用导致的报错
- [x] 记录内存占用：纯后台模式 仿真 + Nav2 约 +400 MB，Nav2 启动后约 20–30 s 就绪

## 阶段 1 · 导航跑通与调优

- [x] 用现有地图完整跑通 `navigation_cutting_task`（导航 → 对位 → 扫描 → 切割）
- [x] 修复任务配置文件路径写死为 Docker `/workspace` 的问题
- [x] 对位控制环改用仿真时钟（`use_sim_time`），控制行为不再随电脑快慢变化
- [x] 加入 Gazebo 真值位姿（`/gazebo/model_states`），用真值评估对位误差；单次实测 26.8 mm / 0.57°
- [x] 对位超时改为如实报失败（原来超时也返回成功）
- [x] **性能**：碰撞模型由高精度 STL（约 29.7 万三角面）换为简单几何体：仿真实时率 0.46 → 1.00，gzserver CPU 112% → 36–40%；完整任务耗时约 104 s；激光无自遮挡
- [x] 修复 `scr_description` 在 `--symlink-install` 下仍复制文件的问题（去掉 `USE_SOURCE_PERMISSIONS`），修改 URDF / world 后无需重新编译
- [x] **对位精度**：控制律改为平移与转向解耦同时控制、加最小速度、收敛容差 3 cm / 4.6° → 1 cm / 1°（可在任务 YAML 中配置）。3 次真值误差 7.6 / 5.3 / 4.0 mm（均值 5.6 mm），角度 ≤ 0.65°；完整任务约 64 s
- [ ] **真正的视觉伺服**：目前方块位置写死在代码中，相机检测结果未参与控制 —— 改为由相机检测驱动对位
- [ ] 自动化测量对位误差（多次重复、不同起点，统计均值 / 方差）
- [ ] AMCL、代价地图膨胀、DWB 速度参数调优

## 阶段 2 · 增强 A\* 进入 ROS 系统

- [ ] **C++ 实现增强 A\***，作为 Nav2 全局规划器插件（`nav2_core::GlobalPlanner`）

  - 在 `nav2_params.yaml` 中替换 `NavfnPlanner`，Gazebo 中直接驱动底盘
- [ ] Python 版保留为参考实现，用同一组场景校验 C++ 版正确性并对比耗时
- [ ] 墙面开槽规划节点：读取墙面障碍 → 规划正交轨迹 → 按机械臂工作空间分段 → 生成 `cartesian_cutting` 路径点
